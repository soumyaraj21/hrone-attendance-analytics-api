# REVIEW.md

Itemized defects identified in the original starter `app/main.py` (helpers and endpoints). Note: All cited line numbers refer to the original defective starter code provided in the candidate kit, prior to architectural fixes and expansions. For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72–74) | Returns `{"status": "ok"}` unconditionally without checking if MongoDB is responsive. | Stop or disconnect MongoDB; endpoint still returns `200 OK` instead of required `503 Service Unavailable`. | Execute `client.admin.command('ping')` inside a try/except block; raise `HTTPException(503, "Database unavailable")` if the ping fails. |
| 2 | `compute_late_minutes` (lines 33–37) | Late threshold evaluation `minutes if minutes > 10 else 0` compares truncated minutes instead of elapsed seconds. | Shift `09:30`, punch at `09:40:01`. Rule R2 states this is 10 minutes late, but starter computes `int(601/60) = 10`, evaluates `10 > 10` as False, and returns 0. | Check if total elapsed seconds $> 600$ (10 minutes). If true, return `int(elapsed_seconds // 60)`, else 0. |
| 3 | `compute_late_minutes` (line 35) | Uses naive `.replace()` on punch timestamp without considering IST shift alignment or overnight shifts. | Punch-in for an overnight shift (e.g., 22:00 start) punched at 21:55 or 01:00 produces incorrect negative minutes or wrong day delta. | Convert instant to IST timezone, construct shift start relative to the record's true IST attendance date, and compute floor minutes from shift start. |
| 4 | `compute_work_hours` (lines 40–42) | Uses Python's built-in `round(x, 2)` which applies Banker's rounding (round-half-to-even) instead of standard half-up rounding. | Work duration resulting in `2.525` hours rounds to `2.52` instead of the required `2.53`. | Use `decimal.Decimal` with `ROUND_HALF_UP` precision to round to 2 decimal places. |
| 5 | `compute_overtime` (lines 44–48) | Always anchors `shift_end` on `date_str`. For overnight shifts (`shift_end <= shift_start`), `shift_end` is on the next calendar day. | Overnight shift 22:00–06:00 on 2026-07-06 punched out at 06:40 on 2026-07-07. Starter evaluates end as 06:00 on July 6th, computing ~24.6 hours of overtime. | If `shift_end <= shift_start`, add 1 day to the shift end anchor date before computing difference. |
| 6 | `compute_overtime` (line 47) | Missing the 30-minute threshold check mandated by Rule R3. | Punch out 25 minutes after shift end. Starter returns 25; R3 requires 0 because overtime is counted only if $\ge 30$ minutes. | Add condition: return whole minutes only if elapsed minutes $\ge 30$; otherwise return 0. |
| 7 | `create_employee` (lines 78–86) | Uses check-then-insert (`find_one` followed by `insert_one`), creating a race condition under concurrency. | Send two concurrent `POST /employees` requests with the same `emp_code`. Both pass `find_one` and insert duplicate records. | Create a unique index on `emp_code` at application startup. Catch PyMongo's `DuplicateKeyError` and raise `HTTPException(409, "emp_code already exists")`. |
| 8 | `EmployeeIn` (lines 53–61) | Lacks input validations required by the OpenAPI schema. | Request with invalid `emp_code` (e.g. `"bad"`), malformed email, empty name, or `shift_start == shift_end` passes validation instead of returning 422. | Add Pydantic field validators: regex `^EMP\d{4,6}$` for `emp_code`, email format, string lengths, and model validator ensuring `shift_start != shift_end`. |
| 9 | `create_employee` (lines 82–85) | Sets `created_at` as local naive `datetime.now()` and returns it as a datetime object/string instead of integer epoch milliseconds. | Client response contains an ISO string rather than integer epoch milliseconds required by `Employee` schema. | Store UTC datetime in MongoDB; format outbound response with `created_at` as integer epoch milliseconds. |
| 10 | `list_employees` (line 93) | Off-by-one pagination bug: `skip = page * page_size`. For page 1, skips 20 records, omitting the entire first page! | Query `GET /employees?page=1`; the first 20 employees are skipped and omitted from the response. | Change skip formula to `(page - 1) * page_size`. |
| 11 | `list_employees` (line 94) | `total` counts the whole collection (`count_documents({})`), ignoring the department filter. | Query `GET /employees?department=Sales`; `total` returns 100 instead of matching count 5. | Pass query filter `q` to `count_documents(q)`. |
| 12 | `list_employees` (line 95) | Does not sort results by `emp_code` ascending as mandated by the contract. | `GET /employees` returns items in arbitrary MongoDB insertion order. | Add `.sort("emp_code", 1)` to the cursor. |
| 13 | `punch_in` (line 101) | Does not check if employee exists; crashes with `TypeError: 'NoneType' object is not subscriptable` (HTTP 500) when accessing `emp["shift_start"]`. | Call `POST /attendance/punch-in` with non-existent `emp_code="EMP9999"`; server raises 500 instead of 404. | Check `if not emp: raise HTTPException(404, "Employee not found")`. |
| 14 | `punch_in` (line 102) | Does not truncate timestamps to whole seconds before calculation and storage as required by Rule R1. | Send `punched_at: 1783312500500`; instant is stored and returned with sub-second values. | Truncate epoch milliseconds to whole seconds: `(ts // 1000) * 1000`. |
| 15 | `punch_in` (line 103) | Computes date with `ts.date().isoformat()`, ignoring IST timezone (+05:30) and overnight shift rules (R1). | Overnight shift starting 22:00 IST punched at 01:00 IST gets assigned to current date instead of previous shift date. | Implement IST timezone conversion and Rule R1 overnight shift date assignment logic. |
| 16 | `punch_in` (lines 104–118) | Check-then-insert race condition on `(emp_code, date)` allows duplicate daily attendance records under concurrency. | Send two concurrent punch-in requests for the same employee and date; both pass `find_one` and create duplicate logs. | Create a unique compound index on `(emp_code, date)` at startup. Catch `DuplicateKeyError` and raise `HTTPException(409, "already punched in for this date")`. |
| 17 | `punch_in` (line 119) | Injects extraneous `id` field (`str(res.inserted_id)`) into response document, violating the `AttendanceRecord` schema. | Response payload contains `"id": "..."`, which fails contract schema validation. | Do not add `id`; strictly return fields defined in `AttendanceRecord`. |
| 18 | `PunchInIn` (lines 63–67) | `punched_at` lacks bounds validation; accepts floats, strings, and seconds-looking integers. | Send `punched_at: 1783312500` (seconds); accepted instead of returning 422. | Use custom `EpochMillis` Pydantic validator enforcing `100000000000 <= val <= 4102444800000`. |
| 19 | `PunchInIn` (line 66) | Accepts any arbitrary status string (including `ABSENT` or `LEAVE`) during punch-in. | Send `status: "LEAVE"`; accepted with punch-in timestamps. | Restrict status to enum: `PRESENT`, `WFH`, `ON_DUTY` (default `PRESENT`). |
| 20 | `list_attendance` (lines 144–150) | In-memory processing: loads entire collection into Python memory with `list(db.attendance_logs.find(q))` and sorts in Python. | On ~100k documents, causes massive latency, extreme memory consumption, and potential server OOM crash. | Execute filtering, sorting (`.sort([("date", -1), ("emp_code", 1)])`), and pagination natively in MongoDB. |
| 21 | `list_attendance` (lines 136–141) | Fails to validate `date_from <= date_to`, returning 200 with empty items instead of HTTP 422. | Call `GET /attendance?date_from=2026-07-10&date_to=2026-07-01`; returns 200 instead of required 422. | Validate date range; raise `HTTPException(422, "date_from cannot be greater than date_to")` if violated. |
| 22 | Global / Startup | No application lifespan handler creating database indexes idempotently at startup. | App starts against a clean database without indexes; queries perform full collection scans (`COLLSCAN`). | Implement FastAPI `lifespan` handler to create unique and query indexes on startup. |

## Items Looked At and Decided NOT a Defect

1. **`emp_code` used as primary identifier instead of MongoDB `_id`:**
   The assignment specification explicitly states that `emp_code` is the business identifier assigned by HR, while `_id` is internal to MongoDB and must never appear in API requests or responses.
2. **Calendar dates and shift times stored as plain strings (`YYYY-MM-DD`, `HH:MM`):**
   Per `DATA_MODEL.md`, calendar dates and times of day are intentionally stored as strings to prevent artificial timezone attachment. Only true point-in-time instants are stored as BSON datetimes.
3. **Derived fields (`work_hours`, `late_minutes`, `overtime_minutes`, `half_day`) stored directly in documents:**
   Per `DATA_MODEL.md`, stored derived values are authoritative and must be persisted upon punch-in, punch-out, and regularization so analytics pipelines can read them directly without recomputation.
4. **`history` initialized to empty array `[]` on punch-in:**
   The audit trail (`history`) is reserved strictly for manual corrections (`PATCH`). Original punch-in and punch-out events must never write to `history`.
